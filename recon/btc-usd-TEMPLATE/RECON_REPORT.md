# Coinbase Advanced Trade — Recon Report (BTC-USD) [TEMPLATE]

> **This is a TEMPLATE / reference copy.** The real report is generated by the
> `coinbase_recon` tool against the *live, signed-in* Advanced Trade tab and is
> written to `recon/btc-usd-<timestamp>/RECON_REPORT.md` together with
> `dom-map.json`, `network-map.json`, `behavioral.json`, and `screenshots/`.
> Because recon must run on the operator's Windows host (Chrome on
> `--remote-debugging-port=9222` with a logged-in Coinbase session), it cannot
> be produced inside CI. Run it once locally per the README; the values below
> describe the **expected shape** and the **book-cited analysis lens** so the
> report is reviewable before you ever run it.

_Mode: **OBSERVE_ONLY** — read-only. No orders placed (Hard Constraint #2)._

---

## How to generate the real report

```jsonc
// via the MCP
{ "name": "coinbase_attach" }                 // assert signedIn === true
{ "name": "coinbase_recon",
  "arguments": { "networkSeconds": 60, "sampleSeconds": 30 } }
```

Output: `recon/btc-usd-<ts>/` with the five artifacts.

---

## 1. Order panel — locators & stability (expected)

> **Harris, _Trading and Exchanges_, Ch. 4 "Orders and Order Properties" & Ch. 6
> "Order-Driven Markets".** The order panel is the trader's instrument.

The tool records, for each control, every locator strategy that resolved, ranked:
**1 = data-testid** → **2 = role+name** → **3 = class fragment** → **4 = textContent**.
_(Newman, Building Microservices, Ch. 5 — prefer the most contractual hook.)_

Controls catalogued: Buy/Sell toggle, order-type selector (Market/Limit/Stop-Limit),
amount input, quote-currency toggle (USD/BTC), Place Order button.

## 2. Order book / chart / trades tape (expected)

> **Harris, Ch. 6–7.** level2 = live limit order book; market_trades = realized
> flow. Coinbase typically renders the candle chart on a `<canvas>` (sometimes a
> TradingView iframe); the tool records whichever it finds, with bounding boxes.

## 3. Portfolio / balances (expected)

> **Antonopoulos, _Mastering Bitcoin_, Ch. 4–5; Ammous, _The Bitcoin Standard_,
> Ch. 10.** "Available" vs "Holds" = unspent vs locked. Read from DOM only.

## 4. Network reconnaissance — WebSocket & REST (expected)

> **Kleppmann, _DDIA_, Ch. 11 "Stream Processing".** Coinbase frames carry a
> connection-level `sequence_num`; this enables **at-least-once with gap
> detection**. For **exactly-once** semantics downstream we must dedupe on
> `(channel, sequence_num)` — the append-only journal (Ch. 3) makes replay/dedup
> possible.

**Expected WebSocket:** `wss://advanced-trade-ws.coinbase.com`

**Expected channels:** `heartbeats`, `ticker`, `ticker_batch`, `level2`,
`market_trades`, `candles`, `status`, plus the authenticated `user` channel.
The recon tool records, per channel: subscribe frames the page sent, a 30-second
sample of received frames with byte size and top-level JSON keys, heartbeat
cadence, and reconnect behavior.

**REST endpoints:** the page polls `/api/v3/brokerage/...`. The tool records
method/path/query/cadence so a future pass can *avoid duplicating* them. We do
**not** call them.

**CSP:** captured from response headers. In-page taps run in the page's main
world via `Runtime.evaluate`, which CSP does not block — confirming the ghost
approach is feasible without injection.

## 5. Behavioral recon (expected)

> **Kahneman, _Thinking, Fast and Slow_, Ch. 4.** Demand-loaded channels reveal
> what the UI fetches lazily, so we don't assume data the feed doesn't send.

Safe interactions only (toggle Buy↔Sell, Market↔Limit, scroll book). **No order
is ever submitted** (no Preview/Place Order click).

## 6. What's NOT in this pass

- No orders, no `Place Order`/`Preview Order` clicks.
- No API keys, JWTs, HMAC, or cookie extraction.
- No second WebSocket — we mirror the page's own feed.
